最近改这个网站，写代码已经不是最花时间的部分了。

有时候我说一句“把这个按钮挪一下”，AI 很快就能找到组件、改完、跑检查，然后提交。

真正让我反复折腾的，反而是代码后面的东西。

前两天就碰到一个很典型的问题：代码改了，构建也成功了，OSS 里的文件看起来也是新的，但我打开网站还是旧页面。

继续盯着 React 没有任何意义。

最后查的是缓存。

## 代码是新的，页面还是旧的

现在前端构建出来的 JS、CSS 一般都带内容 Hash。文件内容变了，文件名也会跟着变，所以这种资源可以放心缓存很久。

麻烦的是 HTML。

如果入口 HTML 也被长时间缓存，就可能出现这种情况：新版本已经部署了，CDN 还在给用户旧的 HTML，旧 HTML 又继续引用旧资源。

所以后来部署流程里把两类文件分开处理：

- 带 Hash 的静态资源长期缓存；
- HTML 需要及时重新验证。

这件事本身并不复杂，但它很好地说明了我最近的感受：AI 把组件改对，只能说明组件改对了。手机最后显示什么，还要看后面一整条链路。

```text
代码
 -> 构建
 -> 部署
 -> OSS
 -> CDN
 -> 浏览器
```

哪一层拿了旧东西，结果都可能不对。

## 现在很多问题都在代码后面

以前做一个小功能，我会把大部分注意力放在实现上。

现在实现速度快了，别的问题就更容易冒出来。

比如部署到底有没有真的到线上。

之前流水线里调用 Function Compute 的更新接口成功，我会默认这次部署完成了。后来想想其实不够。平台接受了代码，不代表函数一定能正常启动。

所以现在更新函数以后，还会从真实访问路径请求一次线上接口。它返回预期的认证结果，才算这次发布真的结束。

还有冷启动。

函数最小实例数设成 0 以后，空闲时确实省资源，但第一次请求可能慢。这个问题没办法靠“代码写得更漂亮”解决，只能决定要不要花钱养常驻实例，或者接受等待，然后把前端反馈做好。

这些选择都在代码之外，但最后都会落到用户能不能正常用上。

## 基础设施没变少，只是平时看不到

DNS、HTTPS、CDN、对象存储、自动构建这些东西，正常的时候很安静。

我平时不会打开网站以后想一句“今天 DNS 工作得不错”。

出问题就完全不一样了。

页面打不开先看解析和证书；页面是旧的看缓存；构建成功但线上没变看部署；私人功能慢了看函数是不是冷启动；文件传上去了但列表没有，再去看索引更新和 CDN。

现在 AI 也能帮我查这些问题。它会看部署配置、日志、缓存头，或者一路把请求链路拆开。

但这不代表这些东西消失了，只是排查起来比以前快一点。

## 我现在会多看一眼“发布以后”

这段时间我给网站的部署流程加了不少检查。

例如前端部署以后，会再从线上读取一个版本文件，确认用户真正访问到的就是刚才那次提交。函数部署以后也会实际探活。

这些检查写出来都不算什么大功能，访问网站的人也看不到。

可我现在挺愿意花时间做这些。

因为改页面已经很快了。如果每次改完还要靠我手动刷新、猜缓存、进控制台确认文件，那前面省下来的时间又会从后面花回去。

所以现在我对“完成”的理解比以前晚一点。

代码改完不算，构建成功也不算。

至少得等我在手机上打开它，看到的确实是那个版本。
