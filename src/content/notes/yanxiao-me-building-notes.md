`yanxiao.me` 是我 2018 年买的。

当时在 Namecheap，没想好要干什么。就是觉得有一个自己的域名挺有意思，偶尔拿来配点东西，更多时候其实是闲着。

2021 年我把它转到了 Cloudflare。那几年正好在玩 Pages 和 Workers，免费额度也很适合个人折腾。域名放在那里挺顺手，就一直用了几年。

真正开始把它当成一个网站，是 2025 年。

那时候要做电子婚礼邀请函，而且希望国内访问稳定一点，我又把域名转到了阿里云。婚礼页面做完以后，我没舍得让这个域名重新闲下来，于是慢慢有了现在这些笔记、时间线、私人资源之类的东西。

## 我没买服务器

最早搭站的时候，我第一个排除的就是“买台云服务器装 Nginx”。

不是因为这个方案不好，主要是我不想下班以后再养一台服务器。

一旦机器常驻在那里，系统更新、证书、日志、磁盘、安全配置，这些事情迟早都得管。工作里已经碰得够多了，个人网站没必要再复制一套。

所以公开部分基本都是静态的。React、TypeScript 和 Vite 构建完以后，产物放到 OSS，再由 CDN 提供访问。

```text
浏览器 -> CDN -> OSS
```

这套东西平时几乎不用管。文章也好，页面也好，只要最终变成静态文件，后面就是同一条路。

## 有后端，但平时不让它一直跑

私人资源、登录、临时访问授权这些东西还是需要后端。我这里用的是 Function Compute。

目前最小实例数是 0。没人用的时候不留常驻实例，有请求再启动。

缺点当然有：第一次打开私人功能时，有时候要等几秒。之前我还专门为这个等待改过几次前端，最后干脆把加载过程明确展示出来。比起全年养一个几乎没请求的实例，我更能接受偶尔等一下。

私人内容和公开内容也是分开的。公开文章直接走 CDN；私人内容先认证，再拿临时权限。浏览器不会放长期有效的云服务密钥，上传文件也尽量直接进对象存储，不让后端再中转一遍大文件。

现在登录主要用 Passkey。这个东西也不是为了“显得新”，单纯是我不想自己维护一套密码找回、弱密码和密码存储。

## 发布最好别让我操心

网站更新现在已经自动化了。

我改完内容或者页面，后面的检查、构建和部署由流水线完成。我很少需要为了发一篇文章去登录什么服务器，也不用拖文件到 OSS 控制台。

这点对个人网站挺重要。更新一次如果要做十几个步骤，几个月以后大概率就懒得更了。

我现在比较希望它是这种状态：想改的时候能很快改，平时放着也不用管。

## 花费也还行

现在固定开销主要是域名和 Function Compute 资源包，OSS、CDN 按量付费。以目前的访问量，一年大概两百多元。

详细账我另外写了一篇，这里就不重复算了。

备案这块也已经处理完，ICP 和公安联网备案信息都放在页面底部。既然决定长期在国内访问，这些本来就是网站的一部分。

## 先这样用着

从 2018 到现在，这个域名干过的事情挺杂：测试过 Web 技术，放过婚礼邀请函，现在又成了个人站。

我没有一个“几年内把它做成什么”的计划。现在想写东西就写，觉得某个地方不好用就改一下，偶尔折腾点新功能。

基础设施也先维持现在这样。真有一天访问量大了、动态功能多了，再改也不迟。

这篇先留在这里。以后如果架构又折腾得面目全非，至少还能回来看看当时为什么这么配。
