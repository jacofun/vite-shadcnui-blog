上一篇写完 `yanxiao.me` 是怎么搭起来的之后，我顺手算了一下现在维持这个网站到底要花多少钱。

结果比我原先想的还低一些。

按照目前的使用量，一年大约 **272 元**。

这不是云厂商宣传页上的“最低可做到”，而是我现在这套网站实际采用的资源组合。

## 先算一笔账

目前比较明确的费用有这些：

| 项目 | 当前费用 |
| --- | ---: |
| `yanxiao.me` 域名 | 135 元 / 年 |
| Function Compute | 126 元 / 年 |
| HTTPS 证书 | 0 元 |
| OSS + CDN | 每天不超过 0.03 元 |

Function Compute 使用的是一年 120 万 CU 的资源包，价格 126 元。

OSS 和 CDN 都按量计费。以现在的访问量，两项加起来每天通常不超过 0.03 元。即使直接按每天 0.03 元计算，一年也只有约 10.95 元。

所以：

```text
域名             135.00 元
Function Compute 126.00 元
OSS + CDN         10.95 元以内
-----------------------------
合计              271.95 元以内
```

平均下来，每天大约七毛多。

做完这笔账以后我才发现，目前这个网站最大的成本之一，居然还是我在 2018 年买下的那个域名本身。

## 证书目前没有花钱

HTTPS 现在使用的是免费的个人测试证书，所以暂时没有证书支出。

这也是目前总成本能控制在 300 元以内的一个原因。

如果以后不再使用免费测试证书，改为购买普通 DV 证书，成本会再增加一块。我目前看到的较低价格方案中，WoSign 的 DV 证书大约是 190 元一年。

如果把这 190 元也算进去，整站一年的费用大约会来到：

```text
271.95 + 190 ≈ 461.95 元
```

依然不到 500 元。

当然，证书和云产品的价格以后都可能变化，这里只是记录我现在这个时间点看到的成本。

## 为什么没有为了几秒钟等待养一个常驻实例

这个网站公开部分基本都是静态内容，真正需要后端的地方不多。

动态能力主要交给 Function Compute，而我把最小实例数设置成了 0。

这样做的好处很直接：没人访问的时候，就没有必要为了“随时可能来一个请求”一直保留计算实例。

代价也很直接：第一次访问动态功能时可能会有冷启动。

我实测下来，正常情况下几秒钟就能响应，前端目前按 8 秒这个范围来处理首次连接的等待体验。

如果只看技术指标，当然可以保留一个常驻实例，把这几秒钟尽量消掉。

但放到一个低访问量的个人网站上，我觉得这笔交换不太划算。

一天中绝大多数时间没有人在调用这些动态能力，为了偶尔一次访问快几秒，让实例全年保持运行，对我来说没有太大必要。

所以我最后接受了冷启动。

## 于是基础设施影响到了页面设计

接受冷启动以后，问题就从“怎么彻底消灭等待”变成了“怎么让等待没那么让人困惑”。

最开始页面只有普通的加载状态。

但如果后端刚好在冷启动，几秒钟没有明显反馈，用户很容易怀疑到底是网络断了、页面坏了，还是服务真的还在启动。

后来我给私人认证服务的首次连接做了一个 8 秒圆环倒计时。

它并不会让 Function Compute 启动得更快，只是明确告诉访问者：

> 服务正在启动，这段等待是预期内的。

如果服务提前响应，页面就立即继续；如果超过预期时间，再提示连接时间比正常情况更长。

我挺喜欢这个小改动，因为它正好体现了建这个站时的一种思路：基础设施上的取舍不一定只停留在后台，有时候最后会变成用户真正能看到的交互。

```text
最小实例数 = 0
        ↓
降低空闲计算成本
        ↓
偶尔出现冷启动
        ↓
前端明确展示等待过程
```

对个人网站来说，我更愿意接受这样一个完整的取舍，而不是单独追求某一项指标最好看。

## 我越来越不想提前购买“以后可能用得到”的资源

以前搭一个网站，很容易从“先买一台服务器”开始。

服务器买下来以后，再往里面放 Nginx、应用、定时任务、文件，最后所有东西都跑在一台长期在线的机器上。

这当然很直观，而且很多场景下依然是最合适的方案。

但现在做自己的个人网站，我更喜欢另一种方式：

**需要存文件，就用对象存储；需要分发，就用 CDN；需要执行一点后端逻辑，就临时启动计算资源。**

没有请求的时候，最好什么都不要运行。

对 `yanxiao.me` 来说，这种方式目前刚好合适。

我省下来的其实不只是每个月几十块钱。

更重要的是，我少了一台需要记得打补丁、看磁盘、维护服务状态的服务器。

个人网站本来就是工作之外维护的东西。如果为了让它存在，还要再养一套小型生产环境，我大概很快就会觉得麻烦。

现在一年两百多元的成本，对我来说已经足够让这个站长期放在那里。

至于以后访问量增加、证书方案变化，或者有更多动态能力，再根据真实需求增加资源就好。

我越来越喜欢这种节奏：

**先让资源和现在的需求匹配，等真的需要的时候再扩。**
