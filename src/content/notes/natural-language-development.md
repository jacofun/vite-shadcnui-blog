现在这个网站有前端页面，有登录和身份验证，有私人资源，也用到了对象存储、CDN 和 Serverless。

但有件事情有些反常：**这个网站的代码，我一行都没有写。**

更准确地说，我没有为它准备本地开发环境，没有打开 IDE 修改文件，也几乎没有亲手操作过 Git。大多数时候，我做的事情只有一件：把我想要什么告诉 AI。

## 我没有“让 AI 帮我做个网站”

如果只是输入一句“帮我做一个个人网站”，最后得到的东西大概率不会是我真正想要的。

我和 AI 的交流通常要具体得多。

比如我会告诉它：移动端某个页面不要展示 Footer；播放器的播放键应该放在正中间，快进和快退分别放在左右两侧；Serverless 冷启动可能需要几秒，加载过程应该让用户知道自己还要等多久；某套跨浏览器登录方案太复杂，就删掉，回到更简单的流程。

有时要求甚至只是：

> 这个逻辑太复杂了，前端改动尽可能简单。

或者：

> 只改这里，其他页面的加载方式不要变化。

这些话里没有代码，但里面有产品行为、技术约束、复杂度控制和取舍。

AI 负责把它们翻译成实现。

## 不敲代码以后，我在做什么

以前写一个功能，我习惯从代码开始思考：接口怎么定义、状态放在哪里、组件怎么拆、异常怎么处理。

现在顺序发生了一些变化。

我先描述结果，再不断补充约束：

```text
想法
 ↓
自然语言描述需求
 ↓
AI 阅读现有工程
 ↓
修改代码
 ↓
测试与构建
 ↓
提交
 ↓
自动部署
 ↓
网站更新
```

这并不意味着开发过程里不再需要判断。

恰恰相反，我花在“判断”上的时间变多了。

一个方案是否过度设计？一个交互在手机上是否合理？为了减少一点等待时间，值不值得长期维持另一套复杂逻辑？缓存应该交给 CDN，还是应该在部署产物上明确声明？一个修复会不会影响原来已经正常的功能？

这些问题最终仍然需要人来决定。

我不再负责把每一个判断亲手写成 TypeScript、Shell 或配置文件，但仍然要对最终行为负责。

## 我几乎不用 Git，但 Git 更重要了

这个变化也很有意思。

我没有在自己的电脑上反复执行：

```bash
git status
git add .
git commit
git push
```

但整个网站其实比以前更依赖版本管理。

每一次修改都应该留下明确的变更记录；较大的调整应该先验证；测试和构建通过以后才能进入正式版本；正式版本更新以后，再由自动化流程完成部署。

于是 Git 从一个需要我亲自操作的工具，慢慢变成了 AI 和自动化系统之间的基础设施。

我不太需要关心命令本身，却比以前更在意一次提交里到底改了什么。

## 自然语言也需要足够精确

这种开发方式用了一段时间以后，我越来越觉得，自然语言并没有降低“表达准确”的要求。

“把这里优化一下”通常是一个很差的需求。

“移动端上下滑动时 Footer 不要跟随当前视口变化，私人资源页直接不展示 Footer”，就要好得多。

“加载做得好看一点”也很模糊。

“加载时从 8 秒开始，用进度表达等待；成功后立即结束；超过预期时间再给出提示”，已经接近一份可以直接实现的设计。

以前需要把意图精确地表达给编译器，现在还要先把意图精确地表达给 AI。

自然语言更宽容，但模糊的输入依然会得到模糊的结果。

## AI 也会把事情做复杂

我并不觉得这种方式已经到了可以完全放手的程度。

AI 很容易犯一些熟悉的错误：为了一个简单问题增加一套复杂机制；在没有确认基础设施状态时作出假设；修复一个页面时顺手改变另一个页面；实现了“能工作”的方案，却偏离了原本追求的简单性。

有些功能我让它做出来以后，又让它完整删掉过。

这也是为什么技术背景仍然有价值。

我可以不亲手写缓存控制的命令，但最好知道浏览器、CDN、对象存储和带 Hash 的静态资源之间是什么关系；我可以不亲手实现身份验证，但至少要能判断一种授权流程是否已经复杂到不值得维护。

AI 降低的是实现成本，没有替我承担这些判断。

## “写代码”可能正在变成一件不同的事

传统的软件开发过程大致是：

```text
人的想法
 ↓
人设计
 ↓
人写代码
 ↓
计算机执行
```

而我维护这个网站时，过程越来越像：

```text
人的想法
 ↓
人描述目标和约束
 ↓
AI 阅读和修改系统
 ↓
自动测试
 ↓
自动部署
```

中间那层代码当然没有消失。

React、TypeScript、构建工具、对象存储和云函数都还在那里。只是对我来说，亲手输入代码已经不再是完成一次开发的必要步骤。

我开始更关心系统最终应该是什么样子，以及如何把这件事说清楚。

这大概也是我目前对 AI 编程最直观的感受：**代码能力仍然重要，但“亲手敲代码”和“开发软件”正在逐渐成为两件可以分开的事情。**

顺便说一句，这篇文章也是用同样的方式完成的。

我没有打开工程，没有创建 Markdown 文件，也没有执行 Git 命令。我只是和 AI 讨论我到底想写什么。

最后，我告诉它：

> **可以，请落代码并提交至 main。**
